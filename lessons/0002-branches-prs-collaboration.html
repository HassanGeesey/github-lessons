Day 2 — Branches, PRs & Collaboration

~25 min read + 65 min hands-on

Goal: Understand branching, create a PR, fork a repo, and review code.

Why branches matter

Never commit directly to main. Branches let you isolate work so experiments don't break the live site. The GitHub Flow is:

main branch (live)  ←  feature branch →  Pull Request →  merge

Branching workflow

git switch -c fix-typo       # create + switch to new branch
# ... edit files ...
git add .
git commit -m "Fix typo on homepage"
git push origin fix-typo

Then go to the GitHub URL that gh prints, or open https://github.com/<user>/<repo>/pull/new/fix-typo.

Create a Pull Request

gh pr create --title "Fix typo on homepage" \
  --body "Corrected spelling of 'recieve' → 'receive'"

Or click the green "Compare & pull request" button on GitHub after pushing.

Merging

After review, merge the PR:

gh pr merge --main --delete  # merges to main, deletes branch locally

Forking someone else's repo

A fork is your personal copy of someone else's repo. It's how you contribute to open-source projects you don't own.

# 1. Click "Fork" on the repo's GitHub page
# 2. Clone your fork
gh repo clone <your-username>/<repo>
cd <repo>

# 3. Create a branch and make changes
git switch -c my-feature
# ...edit...
git add . && git commit -m "Add my feature"
git push

# 4. Create a PR from your fork to the upstream repo
gh pr create --base main --head <your-username>:my-feature

GitHub Issues

gh issue create --title "Bug: login fails on Safari" \
  --body "Steps to reproduce: ..." \
  --label "bug" --label "P1"

Issues link to PRs and vice versa. Reference an issue in a commit:

git commit -m "Fix login timeout #42"

GitHub Projects ( Kanban board )

Projects let you drag issues/PRs across columns (Todo → In Progress → Done). Create one at /<owner>/<repo>/projects and link issues by typing # + issue number in a card comment.

  • Merge the PR and verify it appears on main on GitHub
